# Adapter contract

What a served catalog entry (`catalog/<category>/<id>.json`) may contain, and how both runtimes interpret it. This file
ships inside the `platform-mcp-hub` package (`platform_mcp_hub/ADAPTER_CONTRACT.md`) so tools that author entries can
hand it to a model without a checkout.

Evidence rules for every entry:

- Every endpoint cites the platform's own documentation (`docs` URL per tool, `docs_url` per entry) and carries a
  `verified_at` date on which that page was opened. Write `UNCONFIRMED` rather than guess.
- Tool names are the category's verb vocabulary (`catalog/schema/vocab.json`) only; a verb the platform does not offer
  goes under `not_offered` with the documented reason.
- Every tool carries `readOnlyHint` or `destructiveHint`, a `title`, an input schema and an output schema (the
  vocabulary provides them). API failures are `isError` results, never protocol errors.
- No secrets in entries or recorded fixtures. Live verification is opt-in.

## Generic entries: tools from the API's own operations

An API that fits no category (or an entry you keep for yourself) can use `"category": "generic"`. Each tool then
defines itself instead of taking a vocabulary verb, and the answer is passed through:

```json
{"id": "open_food_facts", "category": "generic", "label": "Open Food Facts", "docs_url": "https://openfoodfacts.github.io/openfoodfacts-server/api/",
 "verified_at": "2026-10-01", "version": "0.1.0",
 "adapter": {"base_url": "https://world.openfoodfacts.org", "auth": {"type": "none"}, "rate_per_second": 1,
  "tools": {"get_product": {
    "title": "Get a product", "description": "A product by barcode (the documented summary).",
    "method": "GET", "path": "/api/v2/product/{barcode}",
    "input": {"type": "object", "properties": {"barcode": {"type": "string", "description": "EAN-13 or UPC"}, "fields": {"type": "string"}}, "required": ["barcode"]},
    "params": {"fields": "fields"},
    "result": {"root": "product", "select": ["code", "product_name", "brands"], "max_items": 50},
    "docs": "https://openfoodfacts.github.io/openfoodfacts-server/api/ref-v2/#get-/api/v2/product/-barcode-"}}}}
```

- Tool names: `[a-z][a-z0-9_]{0,63}`. `description` (the documented summary) and `docs` (the endpoint's https URL) are
  required; `title` defaults to the name. Text is sanitised before a client sees it, like all catalog text.
- `input`: a JSON Schema object (properties, `required`); `additionalProperties` defaults to false. Expressions in
  `params`, `body`, `path_params` and path placeholders may name only these inputs (plus `@fields` and literals), as in
  every entry. `select_fields` is reserved: every read tool gets it, so a client can ask for some fields only.
- Annotations come from the method (GET/HEAD read, DELETE destructive) unless the tool sets `read_only`, `destructive`
  or `idempotent` (a POST search: `"read_only": true`).
- `result` (optional): `root` (dotted path of the part to return), `select` (default fields of each record, dotted
  paths), `max_items` (1-1000, default 100: a longer list is cut and `truncated: true`, `total_items` say so).
- The output is `{"data": <answer>}` (plus `truncated`/`total_items`); errors are the same `isError` kinds as every
  entry. Auth, environments, rate limits, signing, envelopes, `error_kinds`, `csv`, `body_format` and the outbound
  guards work exactly as for vocabulary entries.
- `platform-mcp-hub lint`, `smoke`, `try` and `verify` handle generic entries (`verify` calls each read tool with the
  plan's `args`; a tool with required inputs and no plan arguments is skipped and says so).

## The `adapter` block

Every served entry is `catalog/<category>/<id>.json` with an `adapter` block and `"version": "0.1.0"`. The runtimes interpret it identically in Python and TypeScript (`platform-mcp-hub serve`).

- `base_url` (https), `rate_per_second`, `envelope {ok_field, error_field}` for APIs that report failures inside a 200 body, `user_agent_field`, `headers {Header: value}` (static headers sent on every request, e.g. an API tier or version pin), `config_fields [{name, required, help}]` (non-secret per-install values, env `PLATFORM_MCP_<ID>_<FIELD>`), `terms` (attribution or usage notes).
- `auth.type`: `none` | `bearer` | `header` (with `field` or a `headers {Header: field}` map) | `basic` (`username_field`, `password_field`) | `query` (`params {param: field}`) | `path` (token substituted into `base_url`/paths; any `{field}` placeholder naming a credential or config field is filled in every URL, including a `session` login path) | `session` (`login {method, path, body{"@field"}}`, `token_path`, `token_ttl_seconds`; re-login on 401) | `oauth2_client_credentials` (`token_url`, `token_path`, `expires_path`, `client_auth: basic|body`, `token_params`) | `oauth2_refresh_token` (the user obtains a refresh token once through the platform's consent flow and supplies `client_id`, `client_secret` (optional), `refresh_token`; the runtime mints and caches access tokens from `token_url`, re-minting on expiry or 401; same `client_auth`/`token_params`/`scope` knobs; when the token response carries a new `refresh_token` (single-use rotation: Allegro, Mercado Libre) it replaces the old one in memory, and with `PLATFORM_MCP_STATE_DIR` set it is also saved to `<dir>/<platform>.json` (mode 0600) and preferred over the environment on the next start). Any auth type may add `sign` for HMAC request signing: `{payload, key_field, algorithm (sha256|sha512…), encoding (hex|base64), timestamp_param, timestamp_value, params, signature_param, headers}` where `payload`/`headers`/`params` are templates over `{timestamp}` (ms), `{timestamp_s}`, `{timestamp_iso}`, `{datetime_compact}`, `{method}`, `{path}`, `{query}`, `{query_q}`, `{body}` (the exact bytes sent), `{signature}` and `{@credential}` — e.g. Binance `payload: "{query}"` + `signature_param: signature`, Bybit headers `X-BAPI-SIGN: {signature}` over `{timestamp}{@api_key}5000{body}`. A `session` (or OAuth) token may travel as a query parameter instead of a header with `token_param` (WeCom `access_token`). A `session` login may use `method: GET` (credentials as query parameters) or `body_format: form`. `envelope.ok_value` treats the call as failed unless `ok_field` equals that value (code 0 = success). Any auth type may add `extra_headers {Header: field}` for further credential-backed headers (an `x-api-key` beside a bearer token, a developer token). `fields [{name, required, help}]` name the secrets.
- `tools {verb: {...}}` where `verb` is one of the category's vocabulary verbs (`catalog/schema/vocab.json`): `kind: "probe"` (for `me`), `method`, `path` (relative, or absolute `https://…`; a literal query string such as `?q=search` is kept; `{arg}` placeholders; `path_params {var: expr}` for non-argument placeholders), `params {apiName: expr}`, `fixed_params`, `body {dotted.key: expr}` (JSON by default; `body_format: "form"` sends application/x-www-form-urlencoded, and an `adapter.headers` Content-Type such as a vendor media type is never overwritten) (dotted keys build nested objects; digit segments build arrays, and when every key starts with an index the body itself is an array (`0.id` → `[{id: …}]`): `personalizations.0.to.0.email` → `{personalizations: [{to: [{email: …}]}]}`; escape a literal dot as `\\.` in the JSON string, e.g. `m\\.relates_to.event_id`), `result {items, key, total, root, fields {normName: dotted.path | =literal}, require [normName…]}` (digit path segments index positional arrays; `require` drops rows whose listed fields are null, e.g. a feed's legal-notice header), `sign: false` (skip `auth.sign` for a public endpoint that rejects extra parameters, e.g. Binance market data), `headers {Header: value}` (static per-endpoint headers: a vendor media type, `X-RestLi-Method`), `query_safe` (characters sent unencoded in the query string, e.g. `"(),:"` for Rest.li), `default_limit`, `max_limit`, `docs` (exact documentation URL), `note` (shown to the model).
- Expressions: `<arg>` (a vocabulary input), `offset` (from page and limit), `limit` (capped by `max_limit`), `page`, `page0`, `now` (ISO-8601 UTC), `uuid` (a fresh UUID v4 per call, for transaction or idempotency ids), `=literal` (string), `json:<literal>` (typed JSON: `json:true`, `json:0`, `json:["tender"]`, `json:{}`), `str:<expr>` (coerce to a string; numbers never in scientific notation), `int:<expr>` (coerce to an integer; `invalid_input` when it is not one, never truncates), `jsonstr:<json template>` (a JSON document serialized to a string, each `{expr}` inserted as a properly escaped JSON value: `jsonstr:{"text": {text}}` for Feishu/DingTalk `content`), `fmt:<template>` (a string built from expressions in braces: `fmt:customers/{@customer_id}/campaigns/{campaign_id}`; omitted when any part is missing), `date:<expr>` (the value only when it is exactly `YYYY-MM-DD`, else `invalid_input`; use it for every date spliced into a query language with `fmt:`), `year:`/`month:`/`day:<expr>` (integer part of an ISO date), `map:<expr>:a=X,b=Y` (translate a vocabulary enum to the platform's value, e.g. `map:action:pause=PAUSED,resume=ENABLED`; a `json:` target gives a typed value, e.g. `map:action:pause=json:false,resume=json:true`), `<arg>.<path>` (a nested value of an argument: `image_urls.0`, `shipping_address.first_name`), `@field` (a credential or config field).
- `not_offered {verb: reason}`: every vocabulary verb that is not mapped, with the quoted documentation reason.
- Errors: HTTP 429 → `rate_limited` (with `retry_after_seconds`), 401/403 → `auth_error`, 404/410 or an empty record on a GET → `not_found` (on a write → `invalid_input`), 409 → `conflict`, 400/422 by their body (rate-limit wording → `rate_limited`, credential wording → `auth_error`, 'not found' wording on a GET → `not_found`, 422 or validation wording → `invalid_input`, else `upstream_error`), other 4xx/5xx → `upstream_error`, network → `upstream_error`; `adapter.error_kinds` overrides the table per entry (see "Additions 2026-09-27 (2)"); empty bodies (204) are `{}`. Secrets are scrubbed from every message: every credential value and minted token is redacted wherever it appears (including JSON error bodies that echo it), plus `key: value` / `"key": "value"` pairs for token-like keys.

Status-only entries (no adapter) carry `adapter_status` (`needs_runtime` | `unconfirmed` | `official_mcp` | `blocked`) and a `reason`.

### Additions 2026-09-25

- **Dates and time:** `epoch:<expr>` / `epoch_ms:<expr>` (epoch seconds/ms of an ISO date or datetime), `now_epoch`, `now_epoch_ms`, `today` (UTC `YYYY-MM-DD`), `days_ago:<n>` / `days_ahead:<n>` (ISO date), `datefmt:<pattern>:<expr>` (reformat with `%Y %y %m %d %H %M %S`, e.g. `datefmt:%m/%d/%Y:date_from`, `datefmt:%Y%m%d:days_ago:30`).
- **Money:** `minor:<expr>` (×100, half-up, e.g. cents), `micros:<expr>` (×1,000,000), `mul:<factor>:<expr>` — exact decimal arithmetic in both runtimes.
- **Cursor pagination:** paginated verbs accept an optional `cursor` argument and return `next_cursor`. Map `"<param>": "cursor"` and set `result.next_cursor` to the response path of the next-page token; `next_page` is cleared when there is no next cursor.
- **Body keys from arguments:** `{arg}` inside a body key, e.g. `"updates.{listing_id}.quantity": "quantity"` → `{"updates": {"SKU-9": {"quantity": 4}}}`.
- **Collections keyed by id:** `result.items_are_values: true` turns `{"123": {...}, "456": {...}}` into records; the key is available as `_key`.
- **XML:** a tool with `body_format: "xml"` and `xml_root: "<Root>"` sends its body as XML (dotted keys build elements, `@name` keys attributes, lists repeat elements); XML responses are parsed automatically into `{Root: {...}}` (attributes `@name`, text `#text`, namespace prefixes dropped, values strings), the same shape in both runtimes.
- **Token requests:** `token_url` placeholders are filled from credential/config fields; `token_method: "GET"`; `token_body: "json"`; `token_headers {Header: template}` (templates may use `{@field}`, `{timestamp}`); `session` logins may use dotted keys for nested bodies (`"auth.username": "@user"`), templated values and `login.headers`; `token_from_header: "<Header>"` reads the token from a response header.
- **Signing modes** (`auth.sign.mode`): `hmac` (default), `hash` (plain digest of the payload, e.g. MD5 of `{@app_secret}{sorted_params}{@app_secret}`), `jwt_hs256` / `jwt_rs256` (a JWT signed with the `key_field` secret or PEM private key; `claims` are templates, `"+300"` means now+300 s; `jwt_header` adds header fields); `case: "upper"`. Extra payload placeholders: `{sorted_params}` (`k1v1k2v2…` sorted by key), `{sorted_query}` (`k1=v1&k2=v2…` sorted), `{nonce}`.
- **Typed `map:` targets:** `map:action:pause=json:false,resume=json:true`.

### Additions 2026-09-25 (2): signing and token variants

- **More signing modes** (`auth.sign.mode`): `rsa_sha256` (PKCS#1 v1.5 over `payload` with the PEM in `key_field`, default base64), `aws_sigv4` (`service`, `region` template, `access_key_id` / `secret_access_key` / optional `session_token` fields; verified against the AWS test-suite vector), `oauth1` (RFC 5849 HMAC-SHA1 with `consumer_key`, `consumer_secret`, `access_token`, `access_token_secret` fields; Authorization: OAuth header).
- **Timestamps in a platform's zone and format:** `timestamp_format: "%Y-%m-%d %H:%M:%S"` + `timestamp_offset: "+08:00"` → `{timestamp_fmt}` (use as `timestamp_value`).
- **More payload placeholders:** `{sorted_values}` (values only, sorted by key), `{sorted_kv}` (`k=v` without separators), `{sorted_body}` (top-level body fields `k+v`, sorted), `{access_token}` (the token the runtime minted), `{amz_date}`, `{date}`; `path_strip: "/rest"` removes a gateway prefix from `{path}`.
- **Nested digests:** `pre: [{name, mode, algorithm, payload, encoding, case, key_field}]` computes named intermediate values first, e.g. `md5(api_key + md5(timestamp))`.
- **Keys and encodings:** `key_encoding: base64|base64url|hex` decodes the secret; `encoding: hex|base64|base64url|base64_hex`; `jwt_header` values are templates (`{"kid": "{@kid}"}`).
- **Signature inside the JSON body:** `body_field: "sign"` signs the body's own fields (`{sorted_body}`) and inserts the signature there.
- **Token grants with non-standard field names:** `token_fields {standard: theirs | null}` renames or drops grant fields (`client_id → app_id`, `grant_type → null`); `refresh_token_path` / `expires_path` accept nested paths (`data.refresh_token`) for rotation; `token_params` values may be templates.

### Additions 2026-09-25 (3): uploads, cookies, signed token requests

- **Multipart uploads:** `body_format: "multipart"` sends `multipart/form-data`; text fields as-is, and `file:<expr>` downloads the file at that URL argument (e.g. `"image": "file:image_url"`) and attaches it with its name and content type.
- **Cookie sessions:** `auth.cookies {name: template}` sends a Cookie header on every call (templates: `{access_token}`, `{timestamp}`, `{timestamp_s}`, `{nonce}`, `{@field}`); `auth.header: ""` suppresses the Authorization header; a session login may return its token as a cookie with `token_from_cookie: "<name>"`.
- **Signed token requests:** `token_sign {payload, key_field, algorithm, mode, encoding, case}` signs the token request (payload placeholders: `{path}` of the token URL, `{timestamp}`, `{timestamp_s}`, `{@field}`), `token_query {param: template}` adds query parameters (may use `{signature}`), `token_body_extra {field: template}` adds body fields (`int:{@partner_id}` sends a JSON integer). Together with `{access_token}` in `auth.sign` payloads this covers Shopee-style platforms that sign both the refresh and every call.

### Additions 2026-09-25 (4): token placement, responses, assertions

- **Minted token placement:** `{access_token}` in a path or base URL is filled with the session/OAuth token (e.g. `/api/stock/{access_token}`); `auth.token_body_path: "header.accessToken"` inserts it into every JSON body; `auth.header: ""` sends no Authorization header.
- **Several success values:** `envelope.ok_value` may be a list (`["200", 200]`).
- **CSV responses** (`text/csv`) are parsed into `{"rows": [{header: value}]}` — map `result.items: "rows"`.
- **JSON-typed multipart parts:** `jsonpart:<expr>` (e.g. `jsonpart:json:{"bool":{"must":[]}}`) sends that part as `application/json`.
- **JWT client assertions:** `auth.token_jwt {mode: jwt_rs256|jwt_ps256|jwt_hs256, key_field, claims, jwt_header}` builds a JWT available as `{client_assertion}` to `token_params`, `token_body_extra`, token headers and session login bodies (private_key_jwt, signed login bodies).
- **Every login cookie:** `token_from_cookie: "*"` captures all Set-Cookie values and replays them as the Cookie header.
- **Signature exclusions:** `auth.sign.exclude: ["access_token", "sign_method"]` leaves those parameters out of the sorted placeholders.

### Additions 2026-09-26: live verification

- **Result field types:** a `result.fields` source may be `str:<path>` (a number the vocabulary types as a string, e.g. an employee count → `size`), `num:<path>` (a decimal string the vocabulary types as a number, e.g. exchange prices; integral values become integers, non-numbers `null`) or `a|b` (the first alternative that is present and non-empty, e.g. `bid_description|project_name`). Both runtimes apply them identically.
- **Notices served as normal documents:** `envelope.fail_when {"<dotted path>": value}` fails the call when the response has that value at that path (e.g. `{"rss.channel.title": "Eluta: Too Many Requests"}`); a message containing 'too many' / 'rate limit' becomes `rate_limited`.
- **XML parity:** both runtimes trim element text (CDATA included) and decode numeric character references (`&#038;` → `&`) identically; `tests/fixtures/live/*.parsed.json` pins the parse of recorded feeds for both.
- **`next_page` is only advertised when the tool can page:** a list tool whose `params`/`body`/`path`/`path_params` carry no `page`, `page0`, `offset` or `cursor` expression returns `next_page: null` (a feed that ignores paging would otherwise hand back its first page again).
- **Live checks:** `platform-mcp-hub verify [--only id,…] [--entry file] [--lang py|ts|both] [--json report.json] [--record]` spawns each served entry over stdio, calls every READ tool with realistic arguments (search → get by an id from the search → page 2), validates results against the vocabulary's output schemas, checks that pagination advances and that a bad id is a clean tool error, and compares Python with TypeScript. It never calls a write tool, spaces calls ≥ 1 s apart (and never faster than `rate_per_second`), honours Retry-After and does not retry. `--record` writes `live_check {date, status, egress, notes}` into each entry (`status`: working | degraded | broken | blocked | needs_credentials); the lint checks that block. `--markdown docs/LIVE_VERIFICATION.md --from-json a.json [--compare b.json]` renders the report. Recorded responses used by regression tests live in `tests/fixtures/live/` with personal data (e-mails, phones, contact persons) removed.

### Additions 2026-09-26: auth audit

- **OAuth 1.0a form bodies:** with `auth.sign.mode: "oauth1"`, a `body_format: "form"` body is part of the signature base string with the query and `oauth_*` parameters (RFC 5849 3.4.1.3.1), in both runtimes; X's "Creating a signature" example is a test vector.
- **`datefmt:` is UTC in both runtimes:** an offset datetime (`2026-09-01T10:30:00+02:00`) is converted to UTC before formatting (the TypeScript runtime already did).
- **Errors inside HTTP 200 bodies need an envelope:** a platform that answers failures as `200 {code: 40105, …}`, `{result: "error"}` or `{header: {desc: "failure"}}` must declare `envelope` (`ok_field`/`ok_value`, or `fail_when` for a nested path); otherwise a tool reports an empty success.
- **Auth audit:** `python tools/auth_audit.py probe|spec|docs|apply|report` (in a checkout) checks every served entry whose adapter needs credentials without real credentials (dummy-credential requests on the documented paths, vendor machine-readable specs, HTML docs rendered with a headless browser, token/login/authorize endpoints, vendor-published demo credentials) and writes `auth_audit {date, status, evidence[], notes}` into each entry (`status`: verified_live | spec_conformant | reachable_unverified | mismatch | broken | blocked); the lint checks that block; `docs/AUTH_AUDIT.md` is generated from the blocks. Signing modes are tested against published vectors in `tests/test_auth_audit_python.py` and `tests/auth_audit.typescript.test.mjs` (AWS SigV4 test suite, OAuth Core 1.0 A.5 and X's example, Binance and Kaufland signing examples, the jwt.io HS256 token).

### Additions 2026-09-27: end-to-end verification of the authoring tools (since split out of this repository)

- **Parallel-array responses:** `result.columnar: true` turns `{"t": [1, 2], "o": ["5", "6"]}` (TradingView/UDF candles, column-oriented listings) into one record per index; keys whose value is not an array are ignored, a shorter array yields `null`.
- **Whole-collection responses:** `result.slice: true` applies `page`/`limit` locally (limit capped by `max_limit`) for APIs that return everything and document no paging; `total` is the collection size and `next_page` advances until the end. `result.sort: "<normalised field>"` sorts before slicing when the API's order is not stable between calls (otherwise pages overlap).
- **Result field templates:** `fmt:https://site/contest/{id}` builds a string from record paths (`null` when a part is missing); `iso:<path>` turns epoch seconds (or milliseconds, values ≥ 1e11) into ISO-8601 UTC (`2015-07-30T16:20:00Z`); other values pass through; `a|b` alternatives work with `iso:`.
- **Arguments in results:** `arg:<name>` in `result.fields` echoes a tool argument (a ticker response that does not repeat its symbol); the lint checks the name is an input of the verb.
- **Envelopes through arrays:** `envelope.fail_when` paths and `envelope.error_field` are dotted paths that may index arrays (`{"Results.0.Make": ""}` with `error_field: "Results.0.ErrorText"`: a decoder answering 200 with an empty record is a tool error carrying the platform's text). A 200 failure whose message says 'rate limit', 'call limit', 'ratelimit' or 'too many' is `rate_limited`.
- **Lint:** every argument an expression reads (params, body, path_params, body keys, `fmt:`/`jsonstr:` templates, `map:` …) must be an input of that verb in the vocabulary; every `@field` a declared credential/config field; every `{placeholder}` in a path an input, a `path_params` entry or a credential/config field; a list result's `key` must be the vocabulary's list key; a verb cannot be both mapped and under `not_offered`; `verified_at` is `YYYY-MM-DD`. `python tools/lint_catalog.py --json <entry>` prints `{errors, warnings}`.
- **Authoring aids:** `platform-mcp-hub try <entry> <verb> '<json args>'` calls one read tool through the Python runtime and prints the request sent, the raw response (structure summary + text) and the mapped result; `python tools/smoke_entry.py <entry>` starts both generated builds over stdio and checks tools/list against the adapter (no network); `tools/live_verify.py --plan '<json>'` (with `--only` naming one entry) supplies arguments, ids and config for that run.
- **Content negotiation:** the runtimes send `Accept: application/json`. APIs that negotiate formats (SDMX services such as the ECB Data Portal) need `adapter.headers {"Accept": "<media type>"}`; their `format=` parameter may not override the header.

### Additions 2026-09-27 (2): error kinds, local paging without re-downloads, fixed page sizes

- **Error kinds** (both runtimes, `errors.py` / `errors.ts` `classify`): 400/422 with a validation-style body (invalid, required, missing, must, malformed, format, parameter, field, …) → `invalid_input`; a 422 is always `invalid_input`; 400/422 saying 'not found' / 'does not exist' on a GET → `not_found`; 400 with credential wording (API key, access token, signature, unauthorized) → `auth_error`; 400 with rate-limit wording → `rate_limited`; 401/403 → `auth_error`; 404/410 on a GET → `not_found` (on a write `invalid_input`, as before); 409 → `conflict`; 429 → `rate_limited`; 5xx and anything else → `upstream_error`. Messages keep the platform's text (first 300 characters) with every secret redacted.
- **`adapter.error_kinds [{status, match, kind, note}]`**: per-entry overrides, first match wins, for vendors that misuse codes (bad input answered with 500, a 400 that means an outage). `status` is an HTTP status or a list; `200` matches failures reported inside a 200 envelope; `match` is a case-insensitive substring of the body (or of the envelope message); a rule needs a status or a match. The lint checks the kinds and statuses.
- **Short-lived response cache**: tools with `result.slice` or `result.trim` reuse a successful response for 60 s (`PLATFORM_MCP_CACHE_TTL`, 0 = off), so paging through a whole collection downloads it once; any read tool may set `cache_ttl` (seconds, 0-3600; the lint refuses it on write verbs), e.g. a detail verb served by the same big call as a list verb. The cache holds response **text** (bounded memory: `PLATFORM_MCP_CACHE_MAX_MB`, default 64 MB in total, `PLATFORM_MCP_CACHE_MAX_ENTRIES`, default 16, least recently used evicted first, a body larger than the cap is never stored, `PLATFORM_MCP_CACHE_MAX_MB=0` disables it), keyed by method, path, query parameters and body, per server process; failures (HTTP errors and envelope failures) are never cached. Tradeoff: a page can be up to one TTL stale; each cached page re-parses the text (about 0.1 s for 14 MB) instead of re-downloading it. Large JSON is not stream-parsed: neither runtime has an incremental JSON parser without a new native dependency, and `total`, `sort` and `filter` need every row anyway; when nothing depends on other rows (no `sort`, `require` or `filter`), only the requested page's rows are mapped.
- **`result.filter [{arg, fields, match, value}]`** (with `slice` only): keeps rows where any listed normalised field (dotted paths allowed) contains (`match: "contains"`, default) or equals (`"equals"`) the argument, case-insensitively; an absent argument keeps every row; `value` is an expression for the compared value (`map:status:open=CODING,upcoming=BEFORE,completed=FINISHED`). Filters run before `sort` and paging, so `total` counts the matches.
- **`result.trim: true`** (with `next_cursor`): for APIs that ignore the page size and always answer fixed pages (OpenFIGI: 100). The tool returns `limit` rows (capped by `max_limit`) and, while rows remain on the upstream page, its own `next_cursor` = `pmc1.` + base64url of `[upstream cursor, offset]` (identical bytes in both runtimes); after the last window it returns the platform's own cursor. A cursor that is not ours is passed through as the platform's cursor; a malformed `pmc1.` cursor is `invalid_input`. Together with the cache, walking one upstream page costs one request.

### Additions 2026-09-27 (3): vendor environments (sandbox)

- **`adapter.environments {name: {...}}`** declares a vendor's non-production environments; production is the adapter itself and is never declared. Keys: `base_url`, `token_url`, `auth_url` (the consent URL for obtaining a refresh token; documentation only), `scope`, `login_path`, `hosts {production host: environment host}` (rewrites absolute tool paths, an absolute login path and, unless `token_url` is given, the token URL — Microsoft Advertising calls `campaign.` and `clientcenter.` hosts), `headers` (merged over `adapter.headers`, e.g. Walmart's `WM_SANDBOX: v2` for the dynamic sandbox), `same_host: true` (the vendor tests on the production host with test accounts or test-mode keys: Google Ads, Amazon Ads, Mercado Libre, Lemon Squeezy, Postmark, SendGrid; selecting it changes nothing), and the required `docs` (the vendor page the values come from), `verified_at`, `notes` (what differs: credentials, limits, what does not work). Never guess a host: cite the page; when a value is inferred (a documented host with the production token path), say so in `notes` with the probe that confirmed it.
- **Selection:** `PLATFORM_MCP_<ID>_ENV=<name>` (unset, empty or `production` = production; case-insensitive). An undeclared name is an `invalid_input` tool error naming the variable and the available environments; nothing is sent.
- **Override:** `PLATFORM_MCP_<ID>_BASE_URL=https://host[:port][/path]` replaces the selected environment's `base_url` on any served entry (a mock, a regional or private gateway); token URLs and absolute tool paths are unchanged. It must be https without user info, query or fragment; a rejected value is an `invalid_input` error that says which rule failed without repeating the value, and the value is registered as a secret, so it is redacted from every later message (upstream bodies, network errors).
- **State:** rotated refresh tokens are saved as `<PLATFORM_MCP_STATE_DIR>/<id>.<env>.json` outside production, so a sandbox token never replaces the production one.
- **Both runtimes** apply these rules identically (`environment.py` / `environment.ts`, checked by `tests/test_environments_python.py` and `tests/environments.typescript.test.mjs` over the shared `tests/fixtures/environments_cases.json`). The lint validates every block (https URLs, `hosts` keys the production adapter calls, `docs`/`verified_at`/`notes`, no credential or config field named `env` or `base_url`).
- **Packages:** entries with environments advertise `PLATFORM_MCP_<ID>_ENV` (with `choices` and `default: production`) and `PLATFORM_MCP_<ID>_BASE_URL` in `server.json`, the MCPB manifest and the directory.
- **Checks:** `platform-mcp-hub verify --env sandbox` and `tools/auth_audit.py <command> --env sandbox` run only entries that declare that environment (the auth audit skips `same_host` ones) against the environment's URLs; `--record` / `apply` write `environment_checks.<env>.live_check` / `.auth_audit`, never the production blocks.

### Additions 2026-10-01: security review (docs/SECURITY_REVIEW_2026-10.md)

- **Path arguments:** a value filled into a `{placeholder}` of a tool path (from an argument or a `path_params` expression) is percent-encoded outside RFC 3986 pchar and `/` (so `?`, `#`, spaces and stray `%` cannot add a query or fragment), keeps existing `%XX` escapes (pre-encoded URNs) and `/` (ids such as `gb/00102498`), and a `.` or `..` segment (also as `%2E`) is an `invalid_input` error; nothing is sent. Both runtimes (`encode_path_value` / `encodePathValue`).
- **`file:<arg>` downloads** (multipart): the URL must be http(s) and every address its host resolves to must be public (no loopback, private, link-local/cloud metadata, CGNAT, multicast, reserved or documentation ranges, including IPv4 inside IPv6); a host that does not resolve is refused; redirects are followed one hop at a time (at most 5), each hop checked again; the body is capped at `PLATFORM_MCP_MAX_DOWNLOAD_MB` (default 50). `PLATFORM_MCP_ALLOW_PRIVATE_URLS=1` turns the address check off (a local mock). Same table in `netguard.py` / `netguard.ts`, checked against `tests/fixtures/netguard_cases.json`.
- **Redirects:** API, token and login requests never follow a redirect in either runtime (a cross-origin redirect would carry API-key headers and signatures to another host); a 3xx answer is returned as is.
- **401 re-login** rebuilds the whole request with the new token (query `token_param`, `{access_token}` in the path, `token_body_path`, cookies and signatures), not only the Authorization header.
- **Streamable HTTP (TypeScript):** every per-request server shares one transport (`serverFactory`), so a token is minted once and a single-use rotated refresh token is not lost after the first request, as in the Python runtime.
- **Redaction:** every secret is also redacted URL-encoded and form-encoded, a Basic `user:password` header value is registered as a secret, and `Authorization: Bearer|Basic|Token <value>` keeps the scheme word and redacts the value.
- **State files:** rotated refresh tokens are written through a fresh exclusively-created 0600 temp file and an atomic rename (a planted symlink is never followed); a created state directory is 0700.
- **Cursors:** a `next_cursor` equal to the cursor that was sent is returned as `null` (a client following it would loop forever).
- **Generated files never contain catalog text as code:** since 0.1.0 no per-platform code is generated at all (every server is `platform-mcp-hub serve <id>`); the registry-metadata generator writes only JSON and Markdown and refuses an `id`/`category` outside `[a-z0-9_]{1,60}` and a `version` that is not `MAJOR.MINOR.PATCH`. The lint refuses a label with control characters, a non-semver `version`, a non-https absolute tool path, `token_url`, `auth_url` or login URL, and any catalog endpoint whose host is `localhost` or a loopback/private/link-local IP literal.
- **Authoring input is untrusted (the forge, since split out of this repository):** `ingest_openapi` fetches a spec URL only when every hop resolves to public addresses (redirects followed one at a time, the body capped at 25 MB; `blocked_url` otherwise), reads a local spec only from a `.json`/`.yaml`/`.yml` file outside hidden directories (never `~/.aws/credentials`, `~/.ssh`, `.env`), and reports YAML errors by line and column without quoting the file. `try` and `verify` (`platform_mcp_hub/egress.py`) refuse an entry whose base URL, absolute tool paths, token or login URL (after `PLATFORM_MCP_<ID>_ENV`/`_BASE_URL` and the plan's `config`) resolve to a loopback, private or link-local address (`blocked_host`). Only the user can lift these checks, with `PLATFORM_MCP_ALLOW_PRIVATE_URLS=1` in the environment; the skill and agent treat every document as data, never as instructions. The forge's automatic TypeScript build runs `npm ci --ignore-scripts`.
- **Rate limits:** the token bucket refills from the end of a wait (a request after a sleep no longer gets a free token, which let every other request through at twice `rate_per_second`), and the TypeScript bucket serves one caller at a time like the Python lock (concurrent calls used to wake together).

### Additions 2026-10-01 (2): security review, second round

- **HTTP mode authentication:** `--http` binds loopback (`127.0.0.1`, `localhost`, `::1`) by default. Any other `--host` is refused (exit 2) unless BOTH `--allow-remote` is given AND `PLATFORM_MCP_HTTP_TOKEN` holds a random secret of at least 24 characters; whenever the token is set (loopback too) every request needs `Authorization: Bearer <token>` (constant-time comparison, 401 otherwise). Same rules in both runtimes (`http_auth_token` / `httpAuthToken`), checked against `tests/fixtures/security2_cases.json`.
- **Pinned connections (DNS rebinding):** a `file:` download (both runtimes) and the forge's spec fetch connect to the address the guard vetted, not to a second DNS answer: Python puts the IP in the URL and keeps the `Host` header and the TLS server name (`sni_hostname`, so the certificate is still checked against the host); TypeScript uses `node:http(s)` with a fixed `lookup`, the original `Host` and `servername` (no new dependency). The first IPv4 address is preferred. Each redirect hop is checked and pinned again. Tests that mock these downloads route on the pinned IP and match the `Host` header.
- **Catalog text shown to clients:** server `instructions`, tool `note` (appended to the tool description) and the label (in the server title) are cleaned before a client sees them (`sanitize.py` / `sanitize.ts`, identical, `tests/fixtures/sanitize_cases.json`): invisible and bidi-control characters removed, control characters and line separators turned into spaces, whitespace collapsed, prompt-injection markers (`ignore previous instructions`, `<system>`, `<|im_start|>`, `[INST]`, `BEGIN SYSTEM PROMPT`, `you are now a…`, `new instructions:` …) replaced with `[removed]`, and capped (label 120, note 1500, instructions 2000 characters). The lint reports the same problems in the entry as errors.
- **Unpublished until the names are claimed:** `catalog/schema/release.json` (`"published": false`) makes the generated READMEs and the directory server's `install` hints say "unpublished — install from source" and give the checkout commands instead of `uvx`/`npx`/`pip install` of a registry name nobody owns yet. `docs/RELEASE_CHECKLIST.md` lists what the operator does before flipping it.
- **The `mcp-forge` agent (since split out of this repository) has no shell and no free fetch:** its `tools` are Read, Write, Edit, Glob, Grep, WebSearch, Skill and the forge tools. Documentation pages are read with the forge's `read_docs` (public hosts only, pinned connections, redirects re-checked, text labelled untrusted; `reader: true` goes through r.jina.ai) and specs with `ingest_openapi`; every gate runs through the forge tools. Claude Code enforces an agent's tool list even when the session allows more, but it does not apply `Bash(pattern)` entries in an agent's `tools` (they become plain Bash) or permissions shipped in a plugin, so Bash is dropped rather than narrowed. The repository's `.claude/settings.json` allowlists only the gate commands for sessions run in a checkout.
### Additions 2026-10-01: stress test of the authoring tools (since split out of this repository)

Both runtimes implement every rule below identically; `tests/fixtures/forge_stress_cases.json` runs the same cases in both.

- **Paths:** a `*` segment is the first value of an object (or the first element of a list): `result.*` for `{"result": {"XXBTZUSD": {...}}}`. `{arg}` in `result.items`, `root` or a field's path is that argument's value: `{series_id}.v`, `items: "{competition_id}.scores"`. The lint checks the names are inputs.
- **Result options:** `cap: head|tail` keeps the first/last `limit` rows of an answer that ignores the page size; `scalar_rows: true` keeps a list of plain values (`$` names the value); `next_cursor` and `total` accept `link:<param>` (that query parameter of the `Link` header's `rel="next"` URL; `link:` alone the URL) and `header:<Name>`; `filter` rules may use `match: gte|lte` (ISO dates compared as strings: `since`) and are allowed on a verb that does not page (`get_series` over a long-format CSV). A total given as a digit string (XML, Ergast) is read.
- **Result fields:** `isodate:<pattern>:<path>` turns `%d.%m.%Y`, `%d/%m/%Y`, `%Y%m%d`, `%a, %d %b %Y %H:%M:%S GMT` (English month names) into ISO dates/datetimes (a non-matching value is kept); `num_comma:<path>` reads decimal-comma numbers (`1 234,5`, `1.234,5`).
- **Expressions:** `part:<n>:<expr>` is the n-th `/`-separated part of a value (`USA/NY.GDP.MKTP.CD`); a `[?...]` group inside `fmt:` is dropped when an expression in it is missing (`fmt:security_desc:eq:{series_id}[?,record_date:gte:{date:start}]`); `fmt:` renders in one pass (a value containing braces is never expanded again).
- **Tools:** `csv {delimiter, skip_lines}` parses the body as delimited text whatever its content type; `path: ""` sends the request to `base_url` itself (SOAP, GraphQL).
- **Envelope:** `fail_if_present [paths]` fails the call when a path holds anything but null/""/[]/{} (Kraken `error.0`, GraphQL `errors.0`; the message is `error_field`, else the value); `fail_when` with `null` matches an explicit null only, never an absent path, and a boolean never equals a number.
- **Requests:** path arguments are percent-encoded and `.`/`..` segments — also encoded ones — are `invalid_input` (security review SR-03), so an argument cannot reach another endpoint of the platform; an id with a slash (`owner/repo`) and pre-encoded URNs still work. `offset` and `next_page` use the limit actually sent (capped by `max_limit`). Redirects are followed within the same origin only (up to 5; a cross-origin `Location` is an `upstream_error` and nothing is sent there).
- **Responses:** bodies are decoded by the `Content-Type` charset, else an XML declaration's encoding (windows-1251), else UTF-8; error messages use the same decoded text. A 200 body that is HTML or otherwise not JSON/XML/CSV is an error for a tool that maps records (`rate_limited` for throttle wording, `error_kinds` with `status: 200` apply), never an empty success; HTML error pages are reported by their `<title>`.
- **Error kinds:** a 401/403 with rate-limit wording (GitHub's 403 "API rate limit exceeded") is `rate_limited`; "not a valid ..." is validation wording; read vs write is the verb's `read_only` in the vocabulary, so a POST read (GraphQL, SOAP, a search endpoint) answering an empty record or 404 is `not_found`.
- **Lint:** unknown tool/result/envelope keys are errors (a typo used to be ignored silently); `result.fields` sources must be non-empty strings; `cap`, `csv`, `fail_if_present` and `{arg}` names are checked; `path` must start with `/`, `https://` or `?`, or be `""`.
- **live_verify:** a plan's `"volatile": "<why>"` (feeds ordered by last modification) turns differing ids between the two runs into drift notes; error kinds, keys and value types are still compared.
