# Architecture

platform-mcp turns a language-neutral catalog of platform APIs into MCP servers, without generating code per platform.

```
catalog/<category>/<id>.json  ──►  platform-mcp-hub (Python or TypeScript)  ──►  MCP client (stdio or Streamable HTTP)
   adapter block + evidence         runtime interprets the adapter                 tools = the category's verbs
catalog/schema/vocab.json   ──►  verbs, input/output schemas, annotations
```

## Pieces

1. **Catalog** (`catalog/`). One JSON file per platform per category: identity, docs URL and `verified_at`, terms
   notes, discovery facts and, for served platforms, an `adapter` block (base URL, auth, rate limit, one mapping per
   verb with its documented endpoint, `not_offered` reasons). Status-only entries (no adapter) say why a platform is
   not served. The full contract: [`ADAPTER_CONTRACT.md`](ADAPTER_CONTRACT.md).
2. **Verb vocabularies** (`catalog/schema/vocab.json`). Per category: tool names, titles, descriptions, input and
   output JSON Schemas (2020-12) and annotations. Switching platforms never means learning new tools.
3. **Runtimes**. `runtime/python/platform_mcp_hub` (official MCP Python SDK 2.x) and `runtime/typescript` (official
   SDK v2) implement the same contract: credentials from `PLATFORM_MCP_<ID>_*`, vendor environments
   (`PLATFORM_MCP_<ID>_ENV`, `_BASE_URL`), HTTP with a client-side token bucket, auth flows (bearer, header, basic,
   query, path, session logins, OAuth2 client credentials and refresh tokens with rotation, HMAC and OAuth 1.0a
   signing), result mapping, error classification into `isError` results, secret redaction, an outbound URL guard
   with connection pinning, sanitising of catalog text, and provenance in each tool's `_meta`
   (`platform_mcp/endpoint`, `platform_mcp/docs`, `platform_mcp/verified_at`).
4. **CLI** (`platform-mcp-hub`, both packages): `list`, `describe`, `serve <id>` / `serve --entry <file>`,
   `directory`; the Python package adds the authoring tools `lint`, `try`, `smoke` and `verify`.
5. **Directory server** (`platform-mcp-hub directory`): `list_categories`, `list_platforms`, `describe_platform`,
   `search_capabilities` over `catalog/directory.json`, so an agent can find the right platform without loading
   hundreds of tools.
6. **Registry metadata** (`servers/<category>/<id>/`): `server.json` for the MCP registry and an MCPB `manifest.json`,
   both pointing at `platform-mcp-hub serve <id>`, and a README. Generated by `generators/python/gen.py` through
   `tools/gen_all.py`; no per-platform code exists.

## Packaging

One distribution per language, like a library with batteries included:

| | Python (PyPI) | TypeScript (npm) |
|---|---|---|
| name | `platform-mcp-hub` | `platform-mcp-hub` |
| contains | runtime, CLI, directory, lint/try/smoke/verify, the whole catalog, the adapter contract | runtime, CLI, directory, the whole catalog |
| run | `uvx platform-mcp-hub serve <id>` | `npx platform-mcp-hub serve <id>` |

The catalog ships inside both packages (`platform_mcp_hub/catalog`, `<npm package>/catalog`). Lookup order:
`PLATFORM_MCP_HUB_CATALOG`, the packaged copy, then the checkout's `catalog/`.

## Gates

- `platform-mcp-hub lint`: evidence and naming rules, expressions naming real inputs, URLs public and https, no
  secrets, `live_check`/`auth_audit` blocks well formed.
- Contract tests per platform in both languages (`tests/test_<id>_python.py`, `tests/<id>.typescript.test.mjs`).
- Runtime, security and parity tests: `tests/cli.typescript.test.mjs` compares, for every served entry, the tools
  both runtimes build (names, schemas, annotations, descriptions, `_meta`) and the CLI answers of both builds.
- `tools/gen_all.py` produces no diff (CI).
- Live verification (`platform-mcp-hub verify`, opt-in) and the credential-free auth audit (`tools/auth_audit.py`).
